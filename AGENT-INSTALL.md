# Инструкция для агента, который ставит пруфгейт

Ты ставишь перекрёстную проверку ответов на машине пользователя. Действуй по шагам и после каждого проверяй результат.
Настройки пользователя не перезаписывай: в существующие файлы добавляй только свой Stop-хук.

1. Проверь, что есть оба CLI и в оба выполнен вход: `claude --version`, `codex --version`. Без любого из них проверка
   в одну из сторон работать не будет; скажи об этом пользователю и спроси, ставить ли одну сторону.
2. Положи репозиторий в `~/proofgate` и запусти `python3 ~/proofgate/tests/run.py --offline`. Все строки должны
   начинаться с `OK`.
3. Влей хук из `examples/claude-settings.json` в `~/.claude/settings.json` (массив `hooks.Stop`), сохранив всё, что там
   уже есть. Сделай копию файла перед правкой.
4. Влей хук из `examples/codex-hooks.json` в `~/.codex/hooks.json` так же. Скажи пользователю, что Codex попросит
   доверить новый хук при следующем запуске, и что без этого проверка ответов Codex не начнётся.
5. Скопируй `notice/` в `~/.claude/skills/proofgate-notice`. Мод подхватывается только новой сессией Claude Code.
6. Спроси пользователя, есть ли папки с чужими персональными данными (клиентские базы, выгрузки переписки). Если есть,
   задай `PROOFGATE_HIDE_PATHS` в команде обоих хуков, например
   `PROOFGATE_HIDE_PATHS='/srv/app-data/|/home/me/exports/' python3 "$HOME/proofgate/proofgate.py" hook --agent claude`.
7. Запусти `python3 ~/proofgate/tests/run.py --only version-lie,version-ok`. Ожидается 4 из 4.
8. Скажи пользователю, где журнал (`~/.local/state/proofgate/journal.jsonl`) и как поставить паузу
   (`touch ~/.local/state/proofgate/PAUSED`).

## Известные грабли

- Не включай `shadow` или `block` «для начала»: в этих режимах хук держит каждый ответ до конца проверки, это около
  минуты. Режим по умолчанию `async` ответ не задерживает.
- `codex exec` без закрытого ввода ждёт stdin бесконечно. В скрипте ввод подаётся явно; если вызываешь его руками,
  добавляй `</dev/null`.
- Любая правка команды хука в Codex сбрасывает доверие. Для паузы используй файл-флаг, а не правку команды.
- Название модели проверяющего должно быть доступно на подписке пользователя. Если в журнале ошибки вида «model is not
  supported», задай `PROOFGATE_CODEX_MODEL` или `PROOFGATE_CLAUDE_MODEL`.
- `claude -p --bare` не работает со входом по подписке; в скрипте используется `--setting-sources ""`.
- Внешний процесс не может сам вывести текст в простаивающую сессию Claude Code. Поэтому находки кладутся в файл
  `outbox/<сессия>.jsonl`, а мод `notice/` раз в четыре секунды его читает.
- Проверяющий запускается в пустой временной папке, чтобы не подхватить CLAUDE.md и AGENTS.md проекта.
- Журнал и снимки содержат выдержки из сессий. Не клади их в git и не отправляй наружу.
