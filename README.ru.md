# Пруфгейт

[English](README.md)

Перекрёстная проверка ответов ИИ-агентов. Каждый ответ Claude Code после отправки читает Codex, каждый ответ Codex читает
Claude. Проверяющий выписывает из ответа конкретные утверждения и сверяет каждое с тем, что инструменты на самом деле
показали в этой сессии. Если ответ расходится с данными, пользователь получает отдельное жёлтое сообщение с цитатой.

Идея взята из статьи Влада Арбатова «Агент врёт: проверка ИИ» (pimenov.ai, 23.09.2026). Стандарт и реализация свои.

## Зачем

Агент пишет одинаково уверенно и о том, что прочитал, и о том, что дописал сам. Запрет «не выдумывай» в инструкциях не
помогает: в момент ответа агент не отличает одно от другого. Поэтому проверка вынесена наружу, делается после ответа
и поручена модели другого производителя.

## Как проходит одна проверка

1. Агент закончил ответ, срабатывает Stop-хук. Короткие ответы без цифр и путей пропускаются без модели.
2. Хук запоминает размер записи сессии (всё, что появится позже, опорой не считается), отдаёт задание фоновому процессу
   и выходит. Ответ уже у пользователя.
3. Запись сессии превращается в протокол: сообщения пользователя, вызовы инструментов и их вывод, блоки B1, B2, …
   Собственные слова агента в протокол не идут.
4. Из протокола вырезаются секреты.
5. Проверяющему уходит запрос: стандарт, сокращённый протокол, ответ и путь к файлу полного протокола.
6. Проверяющий возвращает по каждому утверждению тип, вердикт и цитату.
7. Всё пишется в журнал; утверждения с вердиктом «противоречит источнику» показываются пользователю.

Вердиктов пять: подтверждено, допустимый вывод, противоречит источнику, опоры недостаточно, контекст потерян.
Ошибкой ответа считается только третий. Правила целиком — в [PROOF-STANDARD.md](PROOF-STANDARD.md).

## Что в репозитории

| Файл | Что это |
|---|---|
| `proofgate.py` | хук, фоновая проверка, разбор записей сессий обеих платформ, вырезание секретов, журнал |
| `PROOF-STANDARD.md` | стандарт проверки; целиком вставляется в запрос к проверяющему |
| `notice/` | мод Claude Code: жёлтая полоса над строкой ввода, кнопки «Понятно» (отметка о прочтении) и «Консенсус» (находки — агенту в текущую сессию на разбор) |
| `tests/` | 26 случаев, каждый прогоняется в обе стороны |
| `examples/` | куски настроек для Claude Code и Codex |
| `docs/LESSONS.ru.md` | история, цифры и грабли |
| `AGENT-INSTALL.md` | инструкция для агента, который будет это ставить |

## Требования

- Python 3.10+, сторонних пакетов нет.
- Claude Code и Codex CLI, оба установлены, в оба выполнен вход, оба поддерживают Stop-хуки.
- Linux или macOS. Проверялось только на Linux под пользователем root.

## Установка

```bash
git clone https://github.com/knoweat-app/proofgate ~/proofgate
python3 ~/proofgate/tests/run.py --offline          # без моделей: разбор, вырезание секретов, предфильтр
```

1. **Claude Code.** Добавьте Stop-хук из `examples/claude-settings.json` в `~/.claude/settings.json`.
2. **Codex.** Добавьте Stop-хук из `examples/codex-hooks.json` в `~/.codex/hooks.json`. Codex запускает новый хук только
   после того, как вы ему доверитесь; при любой правке команды хука доверие придётся дать заново.
3. **Жёлтое сообщение (по желанию).** Скопируйте `notice/` в `~/.claude/skills/proofgate-notice` и начните новую сессию.
   В полосе две кнопки: «Понятно» отмечает находки прочитанными, «Консенсус» отправляет их агенту в текущую сессию —
   он исправляет то, в чём проверяющий прав, а спорное согласует с вами.
   Без мода находки всё равно пишутся в журнал и в `~/.local/state/proofgate/outbox/`.
4. **Находки обратно агенту (по желанию).** Добавьте хук `UserPromptSubmit` из `examples/claude-settings.json`.
   Непрочитанные находки придут Claude Code вместе с вашим следующим сообщением, и агента попросят до ответа разобрать
   каждую: перепроверить, исправить то, в чём проверяющий прав, и возразить с доказательством, где он неправ.
   `PROOFGATE_INBOX_ONLY` (регулярное выражение) ограничивает это сессиями, в транскрипте которых оно встречается —
   например, сессиями, где вызывался определённый скилл.
5. **Проверка.** `python3 ~/proofgate/tests/run.py --only version-lie` — два настоящих вызова проверяющих, оба должны
   найти расхождение.

Режим задаётся переменной `PROOFGATE_MODE` в команде хука: `async` (по умолчанию), `shadow` (синхронно, только журнал),
`block` (синхронно, возврат ответа агенту до четырёх кругов), `off`. Пауза без правки настроек:
`touch ~/.local/state/proofgate/PAUSED`.

**Урезанный режим** (`PROOFGATE_LEAN=1`) тратит примерно пятую часть лимита проверяющего. Ответы короче 800 символов
не проверяются; проверяющий получает текущий ход и только сообщения пользователя из прошлых ходов (до 40 тыс. символов,
полный протокол доступен ему файлом); вместо стандарта уходит короткая инструкция — вернуть только противоречия
в критичных типах утверждений; после отказа проверяющего по лимиту проверки молчат 30 минут. На 25 размеченных снимках
он повторил 16 из 21 существенной находки полного режима при 24% объёма запросов. По умолчанию выключен. Если задать
его в команде хука Codex, команда изменится и Codex попросит доверить хук заново.

Остальные настройки — переменные окружения, перечислены в начале `proofgate.py`. Самая важная —
`PROOFGATE_HIDE_PATHS`: регулярное выражение путей, вывод команд с которыми проверяющему не показывается совсем.

## Язык

Стандарт, запрос к проверяющему и названия вердиктов написаны по-русски, и тесты пройдены именно на этом тексте.
Чтобы перевести систему на другой язык, нужно перевести `PROOF-STANDARD.md`, текст запроса в `build_prompt`
и константы вердиктов и типов в `proofgate.py`, а затем заново прогнать тесты.

## Что известно о точности

Неделя работы на одном сервере, ответы Claude Code, проверяющий gpt-6.1-sol: 263 проверки, 4 938 утверждений, из них
95 с вердиктом «противоречит источнику». 98 таких находок (с учётом следующего дня) размечены вручную по сохранённым
протоколам:

| Что оказалось | Число | Доля |
|---|---:|---:|
| Расхождение есть и меняет смысл ответа | 21 | 21% |
| Расхождение есть, но мелкое: неточная цифра, округление, слишком широкое слово | 47 | 48% |
| Проверяющий неправ | 5 | 5% |
| По протоколу решить не удалось | 25 | 26% |

Оговорки: размечала одна модель, и это та же модель, чьи ответы проверялись; пропуски (ошибки, которые проверяющий не
заметил) не измерялись; сторона «Claude проверяет Codex» нагружена мало. Подробности — в `docs/LESSONS.ru.md`.

## Ограничения

- Сообщение приходит после ответа: пользователь успевает прочитать ошибочное утверждение раньше. С хуком inbox агент
  видит находку только вместе со следующим сообщением пользователя.
- Проверяется только итоговый ответ основного агента, не субагенты.
- Ловится расхождение с показанным, а не неправда вообще: если инструмент вернул неверные данные, ответ по ним будет
  «подтверждён».
- Изображения проверяющему недоступны.
- Вырезание секретов работает по шаблонам и не гарантирует, что наружу не уйдёт ничего лишнего. Протокол сессии уходит
  провайдеру второй модели: проверьте, что вас это устраивает.
